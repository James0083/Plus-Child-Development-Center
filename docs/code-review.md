# 코드리뷰 기준

이 저장소의 변경을 검토할 때 보는 기준입니다. 디자인 값은 [design-system.md](design-system.md)를 따릅니다.

## 아키텍처

- 사이트는 Next.js 정적 내보내기(`output: "export"`)입니다. 서버 기능, API 라우트, 미들웨어를 `app/`에 추가하지 않습니다.
- 서버 코드는 `worker/index.ts`의 `POST /api/consult` 하나입니다. 범위를 넓히려면 먼저 비용과 구조를 검토합니다.
- 유료 기능, 회원, 결제, DB는 보류 상태입니다. 계획은 `docs/archive/`에 있습니다.
- 환경에 따라 달라지는 동작은 빌드 시점에 정해집니다. 날짜처럼 배포 없이 바뀌어야 하는 값은 브라우저에서 확인합니다 (`SchoolReady`).

| 위치 | 넣는 것 | 넣지 않는 것 |
| --- | --- | --- |
| `app/` | 라우트, 메타데이터, 페이지 조립 | 재사용 부품, 긴 문구 목록 |
| `components/ui/` | 페이지와 무관한 공통 부품 | 센터 내용 |
| `components/<페이지>/` | 해당 페이지 전용 부품 | 다른 페이지에서 쓰는 부품 |
| `data/` | 화면에 나오는 문구와 목록 | Tailwind 클래스, 화면 로직 |
| `lib/constants.ts` | 전화, 주소 등 센터 기본 정보와 설정 | 페이지별 문구 |
| `styles/` | 토큰, 공통 스타일, 애니메이션 | 컴포넌트 전용 스타일 |
| `worker/` | 상담 폼 메일 전송 | 화면 코드 |

- `'use client'`는 상태, 이벤트, 브라우저 API가 필요한 컴포넌트에만 씁니다.
- 큰 기능은 조건부로 켜지면 `next/dynamic`으로 불러옵니다 (`ConsultForm`).

## 네이밍

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 컴포넌트 파일과 이름 | PascalCase, 파일당 기본 내보내기 하나 | `ProgramCards.tsx` |
| 컴포넌트 폴더 | 소문자, 페이지나 역할 이름 | `components/programs/` |
| 데이터와 유틸 파일 | camelCase, 내용을 나타내는 이름 | `data/voucher.ts`, `programTone.ts` |
| 변수, 함수, 내보낸 데이터 | camelCase | `consultSteps` |
| 전역 상수 | UPPER_SNAKE_CASE | `CONSULT_FORM_ENABLED` |
| Props 타입 | `컴포넌트명Props` | `SectionProps` |
| 환경 변수 | 공개 값만 `NEXT_PUBLIC_` | `NEXT_PUBLIC_SITE_URL` |
| 이미지 | 소문자와 하이픈 | `activity-wall.jpg` |

코드 형식은 Prettier가 정합니다 (작은따옴표, 세미콜론 없음, 120자). 형식만 지적하는 리뷰는 하지 않습니다.
주석은 코드만 봐서는 알 수 없는 이유가 있을 때 한국어로 씁니다.

## 디자인과 문구

- 색은 토큰으로만 지정합니다. 주황은 행동 버튼에만 씁니다.
- 굵기는 `font-bold`, `font-extrabold`만 씁니다. 글꼴에 없는 굵기는 쓰지 않습니다.
- 페이지 구역은 `Section`, 흰 면은 `card`, 목록은 `BulletList`를 먼저 씁니다.
- 375, 768, 1024, 1440px에서 가로 넘침과 빈 칸이 없어야 합니다.
- 센터가 확인하지 않은 사실을 문구에 넣지 않습니다. 임시 문구는 `[DUMMY]` 주석으로 표시합니다.
- 바우처와 비용 같은 공식 정보는 출처를 확인합니다. 참고 사이트의 글을 그대로 옮기지 않습니다.

## 접근성

- 이미지는 대체 텍스트를 넣고, 장식 아이콘은 `aria-hidden`을 씁니다.
- 페이지마다 `h1`은 하나이고 제목 순서를 건너뛰지 않습니다.
- 모든 조작은 키보드로 가능하고, 닫으면 포커스가 돌아와야 합니다.
- 글자 대비 4.5:1, 터치 영역 44px을 지킵니다.
- 새 창 링크에는 `(새 창)`을 화면 밖 글자로 넣습니다.

## 보안과 개인정보

- 상담 메일은 센터 주소로만 보내고, 수신 주소를 요청 값으로 받지 않습니다.
- Worker 로그에 개인정보를 남기지 않습니다. 오류 코드만 기록합니다.
- 비밀 값은 `NEXT_PUBLIC_`에 넣지 않고 커밋하지 않습니다. `.env.local`은 저장소에 올리지 않습니다.
- 공개 사진은 위치 정보를 지우고, 아동이나 개인 정보가 보이지 않는지 확인합니다.
- 메일 전송 실제 시험 전에는 상담 폼을 켜지 않습니다.
- 개인정보 처리 방식을 바꾸면 `app/privacy/page.tsx`도 함께 고칩니다.

## 의존성

- 사용 실적이 높은 안정 버전 중 최신을 쓰고, 나온 지 7일이 안 된 버전은 피합니다.
- `overrides`를 쓰지 않습니다. peer 경고는 버전 조정이나 패키지 교체로 없앱니다.
- 새 패키지는 직접 구현이나 CSS로 대신할 수 없는지 먼저 봅니다.

## 리뷰 전 확인

```sh
npm run format:check
npm run lint
npx tsc --noEmit
npm run build
```

- 빌드 뒤에 `npx wrangler dev`로 정적 파일과 Worker를 함께 확인합니다.
- 상담 폼을 건드리면 폼을 켠 빌드로 전송과 실패 흐름을 확인합니다.
- 커밋 메시지는 한국어로 쓰고, 제목은 무엇을 바꿨는지 짧게 적습니다.

## 지적 우선순위

1. 개인정보 유출, 비밀 값 노출, 잘못된 수신처
2. 빌드 실패, 기능 오류, 깨진 링크
3. 사실과 다른 센터 정보, 금액, 법적 고지
4. 접근성 위반
5. 아키텍처와 디자인 규칙 위반
