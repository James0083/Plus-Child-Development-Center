# 사용성 개선 계획

공개 미리보기를 보호자 입장에서 직접 사용해 보고 찾은 문제의 개선 계획입니다. 1~4단계를 단계별로 진행하고, 5단계는 실기기에서 확인합니다. 6단계는 도메인을 연결한 뒤 진행합니다.

## 진행 규칙

- 단계마다 따로 커밋합니다. 푸시는 모든 단계가 끝난 뒤 담당자가 직접 합니다.
- 커밋 전에 `npm run format:check`, `npm run lint`, `npx tsc --noEmit`, `npm run build`, 전 페이지 점검을 통과해야 합니다.
- 상담 폼을 고친 단계는 기본, 시연, 폼을 켠 빌드를 모두 확인합니다.
- 입력 규칙은 `lib/consultRules.ts`에 두고 폼과 Worker가 함께 씁니다.

## 진행 현황

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | 바로 고칠 오류 | 완료 |
| 2 | 상담 폼 사용성 | 완료 |
| 3 | 탐색과 연락 편의 | 대기 |
| 4 | 다듬기 | 대기 |
| 5 | 실기기 확인 | 대기 |
| 6 | 검색 색인 | 도메인 연결 후 |

## 기준 측정값

2026년 11월 4일 공개 미리보기에서 휴대폰 화면 조건, 다운로드 1.6Mbps, 지연 150ms로 측정했습니다.

| 항목 | 메인 | 상담 |
| --- | --- | --- |
| 첫 글자 표시 | 12.2초 | 11.7초 |
| 글꼴 미리 받기를 뺀 시험값 | 1.9초 | 1.3초 |
| 전체 전송량 | 2,471KB | 2,280KB |
| 받은 글꼴 파일 | 196개 | 193개 |

## 1단계: 바로 고칠 오류

### 1-1. 글꼴 미리 받기 끄기

- 문제: 글꼴 파일 185개를 먼저 받아 느린 망에서 첫 화면이 약 12초 늦습니다.
- 변경: `app/layout.tsx`의 `Nanum_Gothic`에 `preload: false`를 넣습니다.
- 완료 기준: 같은 조건에서 첫 글자 표시가 메인 3초 이내입니다.

### 1-2. 첫 오류 칸으로 이동

- 문제: 빈 폼을 제출하면 아동 이름이 아니라 연락처 칸으로 이동합니다. 렌더링 중 `register('phone')`을 먼저 호출해 등록 순서가 바뀌었기 때문입니다.
- 변경: `components/consult/ConsultForm.tsx`에서 등록 순서를 화면 순서와 맞춥니다.
- 완료 기준: 빈 폼 제출 시 아동 이름 칸으로 이동합니다.

## 2단계: 상담 폼 사용성

### 2-1. 폼 바로가기

- 문제: 폼이 페이지 1,369px 아래에 있고 바로 가는 버튼이 없습니다.
- 변경: 폼이 보일 때만 상단 연락 카드에 "온라인 신청서 작성" 버튼을 넣어 폼으로 이동시킵니다.
- 완료 기준: 버튼을 누르면 폼 제목이 머리글에 가리지 않고 보이며, 폼을 끈 빌드에는 버튼이 없습니다.

### 2-2. 입력 중 하단 바 숨김

- 문제: 휴대폰 키보드 위로 전화와 카카오 바가 떠서 입력 칸을 가릴 수 있습니다.
- 변경: 입력 칸에 포커스가 있는 동안 `components/layout/FloatingCTA.tsx`의 하단 바를 숨깁니다.
- 완료 기준: 포커스가 있으면 바가 숨겨지고, 벗어나면 다시 보입니다. 실제 겹침은 5단계에서 확인합니다.

### 2-3. 날짜 제한

- 생년월일: 달력에서 미래 날짜를 고를 수 없게 `max`를 오늘로 둡니다.
- 희망 상담일: 달력에서 지난 날짜를 고를 수 없게 `min`을 오늘로 둡니다.
- 일요일: 희망 상담일로 받지 않습니다. 기본 달력은 요일만 막을 수 없으므로, 고르는 즉시 "일요일은 휴무입니다. 다른 날짜를 선택해 주세요."를 표시하고 제출을 막습니다.
- 공휴일: 달력 자료가 필요해 막지 않습니다. 칸 아래에 "공휴일은 휴무입니다. 상담 때 일정을 조정해 드립니다."를 안내합니다.
- Worker: 일요일과 지난 날짜를 함께 거절합니다. 날짜 계산은 입력한 날짜 기준으로 해서 시간대 영향을 받지 않게 합니다. 날짜가 오늘인지는 한국 시간으로 판단합니다.
- 완료 기준: 일요일을 고르면 즉시 오류가 나오고, 화면을 거치지 않은 일요일 요청은 Worker가 400으로 거절합니다.

### 2-4. 상담 내용 글자 수

- 문제: 2,000자를 넘기면 제출 뒤에야 거절됩니다.
- 변경: `maxLength`를 2,000으로 두고 `120 / 2,000` 형식으로 글자 수를 표시합니다. 제한값은 `lib/consultRules.ts`에 두어 Worker와 맞춥니다.
- 완료 기준: 2,000자에서 더 입력되지 않고 표시가 맞습니다.

### 2-5. 시연 문구 정리

- 문제: 시연 모드에서 상단은 "전송되지 않습니다", 동의 안내는 "입력한 내용은 센터 이메일로 전송됩니다"로 서로 다릅니다.
- 변경: 시연 모드의 전달 방법 문구를 "시연 화면에서는 전송되지 않습니다. 실제 신청 내용은 센터 이메일로 전달됩니다."로 바꿉니다.
- 완료 기준: 시연 모드에서만 문구가 바뀌고, 운영 문구는 그대로입니다.

## 3단계: 탐색과 연락 편의

### 3-1. 사진 크게 보기

- 문제: 사진을 연 채 뒤로 가면 페이지를 벗어나고, 큰 사진을 받는 약 1초 동안 로딩 표시가 없습니다.
- 변경: `components/ui/Lightbox.tsx`에서 열 때 방문 기록을 하나 추가해 뒤로 가기로 사진만 닫습니다. 사진을 받는 동안 로딩 표시를 보여 줍니다.
- 완료 기준: 뒤로 가기로 사진만 닫히고 같은 위치에 남습니다. 닫기 버튼, Esc, 바깥 누르기 뒤에 방문 기록이 쌓이지 않습니다.

### 3-2. 푸터와 주소

- 문제: 푸터의 전화와 이메일을 누를 수 없고, 주소를 복사하는 버튼이 없습니다.
- 변경: `components/layout/Footer.tsx`에 `tel:`, `mailto:` 링크를 넣고, `components/home/MapSection.tsx`에 주소 복사 버튼과 복사 완료 안내를 넣습니다.
- 완료 기준: 링크 터치 영역이 44px 이상이고, 복사가 실패하면 주소를 직접 선택할 수 있습니다.

## 4단계: 다듬기

### 4-1. 가로 모드

- 문제: 휴대폰 가로 모드에서 머리글과 하단 바를 빼면 390px 중 261px만 남습니다.
- 변경: 화면 높이가 낮을 때 하단 바를 숨깁니다. 전화는 페이지 안의 버튼으로 걸 수 있습니다.

### 4-2. 프로그램 탭

- 문제: 모바일에서 7개 탭이 약 200px를 차지해 본문이 밀립니다.
- 변경: `components/programs/ProgramTab.tsx`의 탭을 모바일에서 가로로 넘기는 한 줄로 바꾸고, 선택한 탭이 화면 안에 오게 합니다.
- 완료 기준: 탭 영역이 한 줄이고, 페이지 전체가 가로로 넘치지 않으며, 키보드 조작이 유지됩니다.

### 4-3. 글꼴 용량

- 문제: 미리 받기를 꺼도 글꼴 약 2MB는 뒤이어 받습니다.
- 변경: 굵기 400, 700, 800 중 700과 800을 하나로 합치는 안을 전후로 측정하고 화면을 비교합니다.
- 적용 기준: 전송량이 뚜렷하게 줄고 제목과 본문의 구분이 유지될 때만 적용합니다. 적용하면 `docs/design-system.md`도 고칩니다. 적용하지 않으면 측정값과 이유를 이 문서에 남깁니다.

## 5단계: 실기기 확인

자동 시험으로 재현되지 않는 항목입니다. 1~4단계를 푸시한 뒤 공개 미리보기에서 아이폰과 안드로이드로 직접 확인합니다.

- [ ] 이름 칸에 한글을 입력해도 글자가 깨지지 않음
- [ ] 전화번호 칸에 숫자 키패드가 열리고 11자리에서 형식이 바뀜
- [ ] 입력 중 키보드가 입력 칸이나 버튼을 가리지 않음
- [ ] 날짜 칸의 달력이 범위 제한대로 동작함
- [ ] 전화 버튼으로 통화 화면이 열리고 카카오 채널이 열림
- [ ] 사진 크게 보기에서 스와이프와 뒤로 가기가 동작함

## 6단계: 검색 색인 (구글, 네이버)

도메인을 연결하고 정식 공개할 때 진행합니다. 미리보기 주소는 색인되지 않게 유지합니다.

### 사이트 작업

- [ ] 정식 빌드에 `NEXT_PUBLIC_NOINDEX`가 없고 `robots` 차단이 없는지 확인
- [ ] `NEXT_PUBLIC_SITE_URL`을 실제 도메인으로 설정
- [ ] `app/sitemap.ts`, `app/robots.ts` 추가. 미리보기 빌드는 색인을 막도록 구분
- [ ] 페이지마다 고유한 제목과 설명, 대표 주소(canonical) 설정
- [ ] 센터 이름, 주소, 전화, 운영시간을 담은 구조화 데이터(JSON-LD) 추가
- [ ] 제목 구조와 이미지 대체 텍스트 재점검

### 등록 작업

센터 계정으로 진행합니다. 소유 확인 값은 담당자에게 받아 넣습니다.

- [ ] Google Search Console에 사이트 등록과 소유 확인
- [ ] 네이버 서치어드바이저에 사이트 등록과 소유 확인
- [ ] 두 서비스에 사이트맵 제출, 주요 페이지 수집 요청
- [ ] 네이버 플레이스의 홈페이지 주소를 새 도메인으로 연결
- [ ] 블로그와 카카오 채널의 홈페이지 링크 갱신

### 공개 후 정리

- [ ] 중복 노출을 막기 위해 GitHub Pages를 끄고 `.github/workflows/pages.yml` 삭제
- [ ] 두 서비스에서 색인 상태와 오류 확인
- [ ] 센터 이름으로 검색해 노출 확인. 시기는 검색 서비스에 달려 있어 보장할 수 없음

## 진행 조건

- 6단계 전 필요: 도메인 구입, Cloudflare 연결, 실제 메일 수신 시험, 센터 최종 확인 완료
- 실제 메일 수신 시험은 A안(도메인 연결 후 Cloudflare로 시험)으로 진행하며, 수신 주소는 `pluscenter4052@naver.com`입니다.
